## 1. 结论摘要（先看）

我方项目当前优势在于：
- 本地优先治理更严格（`StrictLocal/Hybrid`、Provider 路由约束、Outbox 可审计事件流）。
- Rust 后端契约更统一（Tauri 命令 + SQLite + FTS5 + Lint Patch 闭环）。
- 多格式摄入基础更强（`md/pdf/url/docx/pptx/txt/图片OCR`）。

对标项目领先点在于：
- 产品闭环完整度更高（项目模板化 + 摄入队列 + Deep Research + 图谱洞察 + Clipper）。
- 图谱不是“展示层”，而是“分析层”（社区检测、惊奇连接、知识空白、可操作建议）。
- 查询阶段的上下文预算管理更细（检索、扩展、预算、组装分层）。

建议我方下一阶段主线：
1. 先补“稳定性与吞吐”能力：**持久化 ingest 队列**。  
2. 再补“知识增益”能力：**图谱洞察层 + Embedding 检索融入 RRF**。  
3. 最后补“入口扩张”能力：**Deep Research + Web Clipper**。

## 4. 可借鉴移植包（按优先级）

## 4.1 移植包 A（P0，先做）
- 目标：补齐“稳定吞吐”短板，支持大批量源文件持续摄入。
- 范围：
  - 后端：新增 `ingest_queue_items` 表 + 队列命令（enqueue/list/cancel/retry/start_worker）。
  - 前端：新增队列面板（排队中/处理中/失败/已完成）。
  - 事件：复用 outbox，新增 `ingest_queue_*` 事件。
- 验收：
  - 重启后任务可恢复。
  - 失败任务可重试，处理中任务可取消。
  - 不破坏现有 `ingest_file/ingest_pdf/ingest_url` 路径。

## 4.2 移植包 B（P1，次优先）
- 目标：把图谱从“可视化”升级为“洞察引擎”。
- 范围：
  - 后端：社区检测结果计算（可先纯前端计算，后续后端化）。
  - 前端：新增洞察卡片（孤立页、桥接节点、稀疏社区、异常连接）。
  - 交互：点击洞察高亮图谱节点/边。
- 验收：
  - 至少 3 类洞察可稳定展示。
  - 洞察与图谱联动可回退。

## 4.3 移植包 C（P1，与B可并行）
- 目标：完成 embedding 检索闭环，提升召回覆盖。
- 范围：
  - 后端：从 `page_embeddings` 做相似度检索，返回 top-k。
  - 查询：并入现有 RRF，形成第4路召回。
  - 前端：展示检索策略标签与命中来源（可选）。
- 验收：
  - 关闭 embedding 时行为不退化。
  - 开启后召回页数与命中率可观测提升。

## 4.4 移植包 D（P2，后续）
- 目标：扩展知识输入与探索能力。
- 方向：
  - D1：Deep Research 任务流（依托现有 `ingest_url`）。
  - D2：项目模板（purpose/schema/index/log 快速初始化）。
  - D3：Clipper（先本地接口，后浏览器扩展）。

## 8. 新开发方向 H（2026-04-25 补充）：Agent Studio 移植蓝图

> 背景：A/B/C/D 与 E/F/G 已具备基础能力，下一轮进入“主动创作 + 可持续演进 + 可审计”的新模块建设。  
> 本节作为三方协作的统一蓝图基线，后续实现与验收均以本节为准。

### 8.1 目标与边界

- 模块代号：**H - Agent Studio**（后端 Agent Hub + 前端 Agent Studio）。
- 目标：补齐主动创作路径（主题 → 草稿 → 审批 → 写入 Wiki），并保留完整证据链与事件日志。
- 约束：
  - 严格本地模式下仅允许本地 Provider（Ollama），禁止外部模型 API。
  - 写盘必须走审批流程，禁止静默覆盖。
  - 生成结论必须可追溯到 citations 与来源页面。

### 8.2 总体策略（Rust 80/20）

- 原则：**Rust 优先，不 Rust-only**。
- 80%：选 Rust 参考项目，优先复用架构与实现模式，降低移植摩擦。
- 20%：吸收非 Rust 生态中的机制设计（仅借鉴机制，不搬代码）。

### 8.3 Rust 参考候选与取舍（按优先级）

#### P0（直接借鉴）

1. `0xPlaygrounds/rig`
   - 借鉴点：Provider 抽象、Agent 工作流组织。
   - 取舍：用于统一 Agent 侧 LLM 调用抽象，不替换现有 `LlmProvider` 主链路。
2. `modelcontextprotocol/rust-sdk`
   - 借鉴点：MCP 协议一致性与工具接入模型。
   - 取舍：优先用于 H 模块工具层，不强制改造现有命令体系。
3. `sqliteai/sqlite-memory`
   - 借鉴点：Markdown + SQLite 的记忆层范式（本地优先、可检索）。
   - 取舍：先做 AAAK-lite，不一次性引入复杂同步体系。

#### P1（机制借鉴）

1. `liquidos-ai/AutoAgents`
   - 借鉴点：多 Agent 编排与角色化组织。
2. `yarenty/kowalski`
   - 借鉴点：persona/模板化 agent 结构。
3. `RightNow-AI/openfang`、`smartcomputer-ai/agent-os`
   - 借鉴点：事件审计、长期运行与治理模型。

### 8.4 里程碑（H0 → H4）

1. H0（脚手架）
   - 后端：`agent_runs / agent_run_events / agent_drafts / agent_memories` 表与命令骨架。
   - 前端：左侧导航新增独立分组 `Agent Studio`（与既有模块显著分隔）。
   - 验收：可创建 run、可查看事件流、可结束 run。
2. H1（主动新建 MVP）
   - 主题输入 → 召回相关页面 → 生成结构化草稿（不直接写盘）。
   - 审批通过后才写入 `vault/wiki/`，并更新 `index.md` / `log.md`。
3. H2（记忆增强）
   - 引入 AAAK-lite 记忆压缩层，提升跨轮稳定性与复用率。
4. H3（技能化）
   - 技能模板与版本历史（先人工维护，后续再考虑自动演化）。
5. H4（深度融合）
   - 与 Ask/Research/Lint 联动，形成跨模块任务入口。

### 8.7 B2 双栏改造路线（2026-04-27 补充）

> 场景：用户确认 Agent Studio 采用「B2 双栏（左对话 + 右草稿预览）」为主方向，并要求可连续接力实现。
> 原则：按顺序推进，先交付稳定可用，再叠加审阅深度与流式体验。

1. **B2-Lite（Phase 1，优先落地）**
   - 目标：在不改后端协议前提下，把 Agent Studio 重排为双栏工作区。
   - 范围（前端）：
     - 左栏：记忆芯片 + 对话线程（按 run 渲染）+ 发送入口。
     - 右栏：当前 draft Markdown 预览 + 写入/重写/丢弃动作。
     - 保留调试动作（追加事件/结束 run）到可折叠区，不占主流程。
   - 主要文件：`web/src/{App.tsx,styles.css,types.ts}`，可选 `src-tauri/tauri.conf.json`（默认窗口加宽）。
   - 验收：
     - 用户从单输入即可触发「创建 run + 生成 draft」闭环。
     - 可在双栏内完成选择、预览、审批写盘，不依赖旧列表区块。

2. **B2-Review（Phase 2，审批优先）**
   - 目标：把审批动作从“整篇阅读”升级为“差异优先审阅”。
   - 范围：
     - 右栏增加 `Draft / Diff / Citations` 三标签。
     - 审批前默认落在 Diff 标签；冲突信息与覆盖风险集中展示。
   - 主要文件：`web/src/{App.tsx,styles.css}`，必要时补 `src-tauri/src/state.rs` 的 diff 数据接口。
   - 验收：
     - 用户可先看差异再审批，明显降低整篇扫描成本。

3. **B2-Flow（Phase 3，流式体验增强）**
   - 目标：强化生成过程可见性，支持长文稳定生成与复写。
   - 范围：
     - 右栏先展示结构骨架，再逐段流式填充正文。
     - 左栏保持步骤日志，不灌入大段 token。
     - 支持暂停/继续/基于当前草稿重写（在既有命令可行范围内逐步接入）。
   - 主要文件：`web/src/{App.tsx,styles.css}`，必要时扩展 `tauri-client` 订阅事件。
   - 验收：
     - 生成过程可追踪、不卡 UI、可中断恢复。

4. **接力要求（Claude/Codex/Gemini）**
   - 每轮结束更新：`docs/实施过程记录.md`、`docs/交接状态卡.md`、`docs/dev-status.md`。
   - 每轮必须给出：
     - 当前 phase 完成度（done/in-progress/todo）
     - 变更文件清单
     - Windows PowerShell 手测命令
   - 若受运行策略限制无法并行子代理，必须在实施记录注明原因、时段、影响范围。
