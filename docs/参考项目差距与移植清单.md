## 1. 结论摘要（先看）

我方项目当前优势在于：
- 本地优先治理更严格（`StrictLocal/Hybrid`、Provider 路由约束、Outbox 可审计事件流）。
- Rust 后端契约更统一（Tauri 命令 + SQLite + FTS5 + Lint Patch 闭环）。
- 多格式摄入基础更强（`md/pdf/url/docx/pptx/txt/图片OCR`）。

对标项目领先点在于：
- 产品闭环完整度更高（项目模板化 + 摄入队列 + Deep Research + 图谱洞察 + Clipper）。
- 图谱不是“展示层”，而是“分析层”（社区检测、惊奇连接、知识空白、可操作建议）。
- 查询阶段的上下文预算管理更细（检索、扩展、预算、组装分层）。

建议我方下一阶段主线：
1. 先补“稳定性与吞吐”能力：**持久化 ingest 队列**。  
2. 再补“知识增益”能力：**图谱洞察层 + Embedding 检索融入 RRF**。  
3. 最后补“入口扩张”能力：**Deep Research + Web Clipper**。

## 3. 精细差距矩阵（功能优先）

| 领域 | 参考项目现状 | 我方现状 | 差距判断 | 可移植方案（建议） |
|---|---|---|---|---|
| 摄入任务编排 | 持久化串行队列、失败重试、取消、恢复（重启后继续） | 以命令式摄入为主，缺少统一任务队列层 | 高 | 新增 `ingest_queue`（DB 表 + 状态机 + UI 队列面板） |
| 两步摄入质量 | 分析→生成双阶段明确拆分 | 已有 LLM 摄入与实体抽取，但“阶段产物可视化/可审核”弱 | 中 | 增加“分析阶段产物”持久化与可视化 |
| 图谱能力 | 关联权重模型 + Louvain + 洞察（惊奇连接/知识空白） | 已有图谱、筛选、局部子图（C2进行中） | 高 | 在现有图谱上叠加“社区检测 + 洞察卡片 + 高亮联动” |
| 查询检索策略 | 分词 + 向量 + 图扩展 + 上下文预算组装 | FTS + RRF（三路）已具备，embedding 已落库但未参与检索融合 | 高 | 增加 RRF 第4路：embedding 相似召回 |
| Deep Research | 多查询 web search → 综合 → 写回 wiki → 自动再摄入 | 暂无 | 高 | 新增 `research_tasks` 与 `ingest_url` 复用链路 |
| 审核流（HITL） | Review 项结构化、可异步处理 | Lint patch 能力强，但“摄入审核队列”未形成产品面 | 中 | 复用 patch 思想扩展到 ingest 审核项 |
| 多项目体验 | 模板化项目创建（purpose/schema预置） | 单项目/单vault工作流为主 | 中 | 引入“项目模板初始化器” |
| 外部采集入口 | Chrome Clipper + 本地守护服务 | 暂无原生剪藏链路 | 中高 | 先实现简版 HTTP clip 接口，再补扩展 |
| 会话持久化 | 多会话、引用信息持久化完善 | Ask 多轮会话有，但长期存储与会话治理可加强 | 中 | 增加会话实体化存储与会话管理 UI |
| 安全与治理 | 功能完整但本地治理策略较宽 | StrictLocal 策略与模式约束更强 | 我方优势 | 保持现有模式治理，不回退 |

## 4. 可借鉴移植包（按优先级）

## 4.1 移植包 A（P0，先做）
- 目标：补齐“稳定吞吐”短板，支持大批量源文件持续摄入。
- 范围：
  - 后端：新增 `ingest_queue_items` 表 + 队列命令（enqueue/list/cancel/retry/start_worker）。
  - 前端：新增队列面板（排队中/处理中/失败/已完成）。
  - 事件：复用 outbox，新增 `ingest_queue_*` 事件。
- 验收：
  - 重启后任务可恢复。
  - 失败任务可重试，处理中任务可取消。
  - 不破坏现有 `ingest_file/ingest_pdf/ingest_url` 路径。

## 4.2 移植包 B（P1，次优先）
- 目标：把图谱从“可视化”升级为“洞察引擎”。
- 范围：
  - 后端：社区检测结果计算（可先纯前端计算，后续后端化）。
  - 前端：新增洞察卡片（孤立页、桥接节点、稀疏社区、异常连接）。
  - 交互：点击洞察高亮图谱节点/边。
- 验收：
  - 至少 3 类洞察可稳定展示。
  - 洞察与图谱联动可回退。

## 4.3 移植包 C（P1，与B可并行）
- 目标：完成 embedding 检索闭环，提升召回覆盖。
- 范围：
  - 后端：从 `page_embeddings` 做相似度检索，返回 top-k。
  - 查询：并入现有 RRF，形成第4路召回。
  - 前端：展示检索策略标签与命中来源（可选）。
- 验收：
  - 关闭 embedding 时行为不退化。
  - 开启后召回页数与命中率可观测提升。

## 4.4 移植包 D（P2，后续）
- 目标：扩展知识输入与探索能力。
- 方向：
  - D1：Deep Research 任务流（依托现有 `ingest_url`）。
  - D2：项目模板（purpose/schema/index/log 快速初始化）。
  - D3：Clipper（先本地接口，后浏览器扩展）。

## 5. 非目标与约束

- 不破坏现有契约：`index.md` / `log.md` / citations / task events 一致性必须保持。
