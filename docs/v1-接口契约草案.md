# v1 接口契约草案（第 1 轮）

本文用于对齐 `web` 与 `src-tauri` 的命令交互结构，当前为骨架阶段契约。

## 1. 命令列表

1. `get_app_overview() -> AppOverview`
2. `set_mode(mode: AppMode) -> ModeChangeResult`
3. `get_recent_logs() -> LogEntry[]`
4. `get_recent_wiki_pages() -> WikiPageItem[]`
5. `search_wiki_pages(keyword: string) -> WikiPageItem[]`
6. `get_wiki_page_detail(page_path: string) -> WikiPageDetail`
7. `get_wiki_page_citations(page_path: string) -> WikiPageCitationItem[]`
8. `run_lint() -> LintReport`
9. `get_llm_status() -> LlmStatus`
10. `init_vault(vault_path: string) -> VaultInitResult`
11. `ingest_markdown(source_path: string) -> IngestResult`
12. `get_default_paths() -> DefaultPaths`
13. `query_ask(question: string) -> QueryAnswerResult`
14. `query_ask_with_options(question: string, options?: QueryAskOptions) -> QueryAnswerResult`
15. `get_query_settings() -> QuerySettings`
16. `set_query_top_k(top_k: number) -> QuerySettings`
17. `save_query_answer(input: SaveQueryAnswerInput) -> SaveQueryAnswerResult`

## 2. 类型约定

### `AppMode`
- `Hybrid`
- `StrictLocal`

### `AppOverview`
- `app_name: string`
- `mode: AppMode`
- `vault_path: string`
- `recent_log_count: number`
- `pending_tasks: number`
- `supported_modes: AppMode[]`

### `ModeChangeResult`
- `previous_mode: AppMode`
- `current_mode: AppMode`
- `strict_local_enabled: boolean`

说明：
- `set_mode` 调用成功后，运行模式必须持久化到本地配置文件。

### `LogEntry`
- `id: number`
- `level: "Info" | "Warn" | "Error"`
- `message: string`
- `created_at: string` (`ISO-8601`)

说明：
- 第 2 轮仅要求可读最近日志与模式切换日志，不要求完整任务审计字段。

### `LlmStatus`
- `provider: string`
- `base_url: string`
- `model: string`
- `healthy: boolean`
- `message: string`
- `mode: AppMode`

### `WikiPageItem`
- `title: string`
- `path: string`
- `display_path?: string`（可选，优先用于 UI 展示的友好路径）
- `summary: string`
- `updated_at: string`（Unix ms 字符串）

### `WikiPageDetail`
- `title: string`
- `path: string`
- `display_path: string`（后端返回的友好展示路径，默认去除 Windows `\\?\` 前缀）
- `content: string`
- `updated_at: string`（Unix ms 字符串）

### `WikiPageCitationItem`
- `cited_page_path: string`
- `cited_page_display_path?: string`（可选，UI 友好展示路径）
- `score: number`
- `excerpt: string`
- `target_exists: boolean`

### `LintIssue`
- `code: string`
- `severity: string`
- `message: string`
- `path?: string`
- `suggestion: string`

约定：
- `severity` 使用 `info | warning | error`。

### `LintReport`
- `mode: AppMode`
- `checked_at: string` (`ISO-8601`)
- `summary: string`
- `severity_stats: { error: number; warning: number; info: number }`
- `issues: LintIssue[]`

### `VaultInitResult`
- `vault_path: string`
- `created_paths: string[]`
- `message: string`

### `IngestResult`
- `source_path: string`
- `raw_path: string`
- `wiki_path: string`
- `message: string`

### `DefaultPaths`
- `vault_path: string`
- `ingest_source_path: string`

### `QueryCitation`
- `page_path: string`
- `display_path?: string`（可选，UI 友好展示路径）
- `score: number`
- `excerpt: string`

### `QueryAnswerResult`
- `question: string`
- `answer: string`
- `search_strategy?: "empty" | "fts" | "scan"`（检索策略）
- `answer_strategy?: "llm" | "rule"`（回答生成策略；兼容历史值 `llm_synthesis | rule_fallback`）
- `citations: QueryCitation[]`
- `matched_pages: string[]`
- `mode: AppMode`
- `checked_at: string`（Unix ms 字符串）

### `QueryAskOptions`
- `top_k?: number`（范围 1..=8，默认 3）

### `QuerySettings`
- `top_k: number`
- `min_top_k: number`
- `max_top_k: number`

### `SaveQueryAnswerInput`
- `question: string`
- `answer: string`
- `citations: QueryCitation[]`
- `title?: string`

### `SaveQueryAnswerResult`
- `wiki_path: string`
- `page_title: string`
- `message: string`

说明：
- `query_ask` 在 v1.1 起优先使用 SQLite `fts_pages` 召回候选页，再生成结果中的 `citations` 与 `matched_pages`。
- 当 FTS 不可用或候选为空时，后端可降级为文件扫描，字段结构保持不变。
- v1.2 起检索 token 支持中英混合：英文 token + 连续中文片段与 2-gram；排序分数包含正文命中、标题命中加权、短语命中加权。
- v1.3 起支持 `query_ask_with_options`，可配置 `top_k`，并保持对旧命令 `query_ask` 的兼容。
- v1.4 起支持 Query 参数持久化：`get_query_settings` 读取运行时配置，`set_query_top_k` 写回 `.runtime/app-config.json`。
- v1.5 起支持 Query 结果落库落盘：`save_query_answer` 会写入 `vault/wiki`、同步 `index.md`、追加 `log.md`，并更新 SQLite/FTS。
- v1.6 起 Query 保存会同步写入 `citations` 关系表；Lint 增加 `BROKEN_CITATION`（引用目标缺失）检测。
- v1.7 起 Ingest 按内容哈希去重：重复内容直接复用既有 `raw/wiki` 页面，不重复追加 `index.md` 与任务记录。
- v1.8 起支持 `search_wiki_pages`，可按标题/摘要/路径关键字筛选页面列表。
- v1.9 起支持 `get_wiki_page_detail`，在 UI 中可直接预览页面正文；后端限制只允许读取当前 `vault/wiki` 目录内 Markdown。
- v1.10 起支持 `get_wiki_page_citations`，可在页面预览区查看引用明细并标注目标是否存在。
- v1.11 起 `get_wiki_page_detail` 返回 `display_path`，用于 UI 展示友好路径（去掉 Windows verbatim 路径前缀）；前端统一优先显示 `display_path`，缺失时回退原始路径字段。
- v1.12 起后端统一补齐友好路径字段：`QueryCitation.display_path`、`WikiPageItem.display_path`、`WikiPageCitationItem.cited_page_display_path`，前端可直接展示无需再依赖纯回退逻辑。
- v1.13 起新增 `get_llm_status`：返回本地 Ollama 连通状态（模型、地址、健康状态、提示信息），前端在“运行模式”区域展示 LLM 可用性。
- v1.14 起明确 `QueryAnswerResult.answer_strategy`：回答策略使用 `llm | rule`，与检索策略（`empty | fts | scan`）分离；前端继续兼容历史值 `llm_synthesis | rule_fallback` 的展示。
- v1.15 起前端 Ask 面板显示 `search_strategy`（`empty | fts | scan`），用于直观看到当前 Query 召回路径。
- v1.16 起 `run_lint` 返回 `severity_stats`（`error/warning/info`），前端 Lint 面板展示严重级别数量分组；若字段缺失则回退按 `issues` 计算。

## 2.1 本轮 PowerShell 验证命令（FTS5）

```powershell
Set-Location E:\llm-wiki\src-tauri
cargo test
cargo tauri dev --config .\tauri.conf.json
```

应用内手动验证：
1. 初始化 Vault。
2. 执行至少一次“示例摄入”。
3. 在 Ask 面板输入问题并执行 Query，确认返回命中页与引用。
4. 重新执行 Query，确认结果稳定返回（验证索引路径可复用）。
5. 修改 TopK 并点击“保存参数”，重启应用后确认 TopK 仍为保存值。
6. 执行 Query 后点击“保存回答到 Wiki”，确认 `vault/wiki` 出现 `query-*.md`，并且 `index.md/log.md` 同步新增记录。

## 3. 演进规则

- 第 2 轮开始，前端类型定义与 Rust `serde` 模型必须保持字段同名。
- 新增字段采用向后兼容方式，不直接删除旧字段。
- 结构变更必须同步更新：
  - `src-tauri/src/models.rs`
  - `web/src/types.ts`
  - 本文档
