# 多 Agent 通信与交接协议（Claude Code / Codex / Gemini）

> 生效日期：2026-04-20  
> 适用仓库：`/mnt/e/llm-wiki`

## 1. 目标

在“不会同时修改代码”的前提下，确保三方 Agent 任意接手后都能在 5 分钟内明确：
- 当前做到哪一步；
- 哪些文件可改、哪些不可改；
- 下一步应执行什么；
- 当前风险和阻塞是什么。

## 2. 核心原则

- 单写者接力：任一时刻只允许一个 Agent 进入代码写入阶段，其他 Agent 只读或等待交接。
- 先同步再动手：接手 Agent 未完成上下文同步与基线检查前，不允许开始改代码。
- 事实落盘：所有关键决策、变更、验证、阻塞必须写入仓库文档，不依赖聊天窗口记忆。
- 失败显式化：验证失败、环境缺失、串行原因必须明确记录，禁止“看起来完成”。

## 3. 强制通信载体

每一轮都必须同步以下 4 个载体：

1. `docs/交接状态卡.md`：面向下一位 Agent 的快速状态快照（最新状态单点事实源）。
2. `docs/实施过程记录.md`：完整审计轨迹（关键决策、验证结果、风险与后续）。
3. `agents.md`（重点 §18）：项目全局状态、已完成项、下一轮 TODO、基线结果。
4. Git 事实：`git status`、最新 commit、变更文件列表。

## 4. 接手流程（必须按顺序）

1. 读取：`agents.md`、`docs/实施过程记录.md` 最新 3 条、`docs/参考项目差距与移植清单.md`、`docs/交接状态卡.md`。
2. 执行 §16.3 基线检查（无法执行时必须记录原因和影响范围）。
3. 核对文件所有权与本轮目标，确认无冲突后再开始改动。
4. 在 `docs/交接状态卡.md` 更新“当前接力 Agent / 轮次 / 目标 / 文件所有权 / 阻塞项”。
5. 在 `docs/实施过程记录.md` 新增“接手声明”或“开工记录”。

## 5. 交接输出规范（结束本轮前）

结束本轮时必须一次性交付以下内容：

1. 改动文件清单（按前端/后端/文档分类）。
2. 自动化验证结果（通过/失败 + 失败原因）。
3. 用户侧 PowerShell 手动验证命令。
4. 未完成项 TODO（必须可执行，不能写空泛描述）。
5. 风险与回滚点（若有）。
6. 更新 `docs/交接状态卡.md` 为“可接手”状态。
7. 更新 `agents.md` §18（已完成、下一步、基线）和 `docs/实施过程记录.md`。

## 6. 标准交接消息模板（Agent 对 Agent）

每轮结束时，主控 Agent 必须使用以下模板写入交接信息（可同步到聊天消息）：

```md
## Handoff Packet
- round_id: RYYYYMMDD-XX
- from_agent: <Claude|Codex|Gemini>
- to_agent: <Claude|Codex|Gemini|Any>
- objective: <本轮目标>
- scope_done: <已完成范围>
- files_changed:
  - <path>
  - <path>
- tests:
  - <command>: <pass|fail> (<关键输出或失败原因>)
- manual_ps:
  - <PowerShell command>
- open_todos:
  - <TODO-1>
  - <TODO-2>
- risks:
  - <风险描述>
- next_first_step: <下一位 Agent 接手后第一步>
```

## 7. 文件所有权与冲突处理

- 单轮内每个 Agent 只能修改已分配文件；跨范围修改必须先经主控重分配并记录。
- 若发现他人未提交改动或意外脏树：
  - 立即暂停写入；
  - 在 `docs/实施过程记录.md` 记录发现时间、文件、影响；
  - 由主控决定“吸收/隔离/延后”后再继续。
- 禁止自行覆盖他人变更，禁止使用破坏性命令清理现场。

## 8. 状态定义（与任务状态对齐）

- `queued`：已排队，未开始。
- `running`：正在实现。
- `reviewing`：代码已完成，待验证或待用户确认。
- `applied`：已合入并完成交接更新。
- `failed`：执行失败并记录错误上下文。

`docs/交接状态卡.md` 必须明确当前状态值。

## 9. 快速判定“可安全接手”

同时满足以下条件，下一位 Agent 才能开始编码：

1. `docs/交接状态卡.md` 已更新为最新轮次且有 `next_first_step`。
2. `docs/实施过程记录.md` 存在本轮记录，含验证与 TODO。
3. `agents.md` §18 已同步本轮完成项与下一步。
4. 文件所有权清晰，无冲突文件。

若任一条件不满足，只能先补文档，不得直接改代码。
