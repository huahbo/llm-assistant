# 测试与验证规范

> **所有 Agent（Claude Code / Codex / OpenCode）每完成一个大轮次，必须按本规范执行测试并更新 `docs/dev-status.md` 基线数字。**

---

## 0. 环境说明（重要）

| Agent | 运行环境 | 执行命令 |
|---|---|---|
| Codex | WSL（Linux） | `cargo test`、`npm run typecheck`、`npm run test -- --run` |
| OpenCode | Windows 本机 | PowerShell：`cargo test`、`npm run typecheck` |
| Claude Code | Windows 本机 | bash/PowerShell 均可 |

**差异注意：**
- WSL 侧执行 `npm i` 会被 `@tauri-apps/cli-win32-x64-msvc` 平台限制拦截，跳过即可。
- WSL 侧 Rollup 原生模块 `@rollup/rollup-linux-x64-gnu` 可能缺失，前端单测失败时以 Windows 本机结果为准。
- Rust 测试（`cargo test`）在 WSL 和 Windows 均可运行，结果应一致。

---

## 1. 核心原则

1. **测试随代码提交**：新增逻辑必须同轮次附带测试，不允许"下一轮再补"。
2. **测试不进包**：Rust 测试全部在 `#[cfg(test)]` 块内，`cargo tauri build` 打包时完全排除，对产物零影响。
3. **能自动化的不手测**：凡是纯逻辑、文件 I/O、DB 操作，必须自动化测试；只有下表中的场景才交给用户手测。
4. **手测前必须告知**：确认无法自动化后，明确写出"需手测"并提供具体步骤。

---

## 2. 自动化测试覆盖范围

### 2.1 必须自动化（写 Rust 单测）

| 场景 | 测试位置 | 示例 |
|---|---|---|
| 新增 Tauri 命令的核心逻辑 | 同文件 `_impl` 方法 + 测试 | `approve_agent_write_impl` |
| 状态流转（pending → applied/rejected） | `state.rs #[cfg(test)]` | 审批写入链路 |
| 文件 I/O（写入/patch/读取） | 用 `make_temp_dir` 隔离 | write_wiki / edit_wiki |
| DB CRUD（insert/query/delete） | `db.rs #[cfg(test)]` | FTS 查询、软删除 |
| 业务规则/策略判断 | 策略模块测试 | shell policy 决策 |
| 数据解析/格式转换 | 就近测试 | JSON 决策解析 |
| PathGuard 路径校验 | `agent_policy.rs` 测试 | 非 wiki 路径拒绝 |

### 2.2 必须自动化（写 TypeScript 单测）

| 场景 | 测试位置 |
|---|---|
| tauri-client 参数构造函数 | `web/src/__tests__/` |
| 纯数据转换 / 状态推导逻辑 | 就近 `.test.ts` |

### 2.3 无法自动化（需用户手测）

| 场景 | 原因 |
|---|---|
| UI 渲染与布局 | 需要视觉判断 |
| Tauri 窗口行为（拖动/缩放/最大化） | 需要 OS 层交互 |
| DWM 边框/阴影视觉效果 | 纯视觉 |
| 真实 LLM 调用质量 | 非确定性 |
| Tauri 原生文件选择器 | 需要 GUI |
| 首次安装 / MSI 包行为 | 需要真实安装环境 |

## 3. 每轮次收口检查清单

完成一个大功能轮次（H 系列）后，提交前必须确认：

```
[ ] cargo test 全部通过，数字写入 dev-status.md
[ ] npm run typecheck 零错误
[ ] 新增逻辑有对应测试（见 §2.1/2.2）
[ ] 无法自动化的场景已在 dev-status.md §活跃TODO 中标注"待手测"
[ ] 手测项目有明确步骤（PowerShell / UI 操作描述）
```

## 4. 测试命令速查

### Rust（WSL / Windows 均可）
```bash
# 全量
cargo test

# 指定模块
cargo test approve_agent
cargo test agent_loop
cargo test db::tests

# 带输出（调试用）
cargo test -- --nocapture
```

### TypeScript（Windows 本机优先）
```powershell
# 类型检查（WSL/Windows 均可）
cd web && npm run typecheck

# 单测（Windows 本机）
cd web && npm run test -- --run
```

---

## 5. 测试文件规范

### Rust
- 测试写在**被测文件同文件**的 `#[cfg(test)] mod tests {}` 块内
- 使用项目内已有的 `make_temp_dir` + `TempDirGuard` 做目录隔离
- 使用 `make_test_state_bare` 构造无 mock 干扰的纯净 state

### TypeScript
- 测试文件放 `web/src/__tests__/` 或与被测文件同目录（`.test.ts` 后缀）
- 不 mock Tauri IPC；只测纯函数和参数构造
